# Plan: migration steps 1–3 (skeleton, leaf packages, lints and machine scripts)

From [the split design](../specs/2026-11-23-prismarine-split-design.md), steps 1–3.
Each step ends in one landing per repo, made by the coordinator: prismarine first behind its gate, then mcsm behind its gate.
Every step keeps mcsm's outputs byte-identical: D1 against the current reference, and the corpus unchanged (a pure move changes no sim code; the corpus runs once at the end of the three steps).

## Step 1: skeleton

1. A pub workspace at the root (`pubspec.yaml`, `analysis_options.yaml`), the analysis rules copied from mcsm's `tools/lint/analysis/`.
2. `tools/lint/`: copies of mcsm's analyze, alloc, same_code, privacy_check, check_links, docs_index and code_shape (with its lexer, rules and scope), with their tests.
   - Paths come from a per-repo config (`tools/lint/config.yaml`: baselines, loose dirs, docs layout, the private dir's env var `PRISMARINE_PRIVATE`), not constants; mcsm keeps working on its copies until step 3.
   - code_shape's rules split into a generic set (file size, comment history, long comments, function length) and rule sets a repo names in its config; the exe-address and season-name rules are written as mcsm's set, which mcsm passes in step 3.
   - privacy_check reads its patterns from `$PRISMARINE_PRIVATE/config/privacy-patterns.txt`; prismarine's list is mcsm's plus game asset prefixes, slice paths and game names, so any game word in code fails.
3. `private/` (gitignored here): its own git repo with `gate/land-gate.sh` (privacy strict, links, docs index, code_shape, analyze and format, alloc, the lints' tests, package tests, clippy and `cargo test` per crate, the sample app's macOS build) and the privacy patterns.
4. `apps/prismarine_sample/`: an empty Flutter app on the patched engine (a window and one cleared frame through Flutter GPU), so the gate builds an app from step 1.
5. Docs: `docs/areas/` gets a page per package as it moves (how it works, how to check it), each rewritten from mcsm's area docs, not duplicated.

## Step 2: leaf packages

Moved verbatim with `git mv`-equivalent history notes in the commit message (mcsm commit and path), renamed, imports rewritten:

| From mcsm | To prismarine | Notes |
|---|---|---|
| `packages/mcsm_kept` | `packages/prismarine_kept` | The alloc lint's markers name it; update the lint's tables in both repos |
| `packages/mcsm_snap` | `packages/prismarine_snap` | Depends on kept |
| `packages/mcsm_math` libm and clamps | `packages/prismarine_math` | The UCRT maths stay in mcsm as `mcsm_math`, now importing `prismarine_math`. The "mixer maths in dmath.rs and libm.dart" rule names both repos |
| `packages/mcsm_jobs` | `packages/prismarine_jobs` | `PRISMARINE_AHEAD_BUDGET_MB`/`_FREE_MB`, reading the `MCSM_*` names as a fallback |
| `packages/mcsm_cargo` | `packages/prismarine_cargo` | Its description points at a memory file; rewrite it |
| `packages/mcsm_pad` | `packages/prismarine_pad` | Its crate's description cites an mcsm doc; rewrite it |

mcsm's side, in one commit: the pubspecs name the prismarine packages pinned by commit; the old packages are deleted; imports are rewritten; the workspace list drops the moved members.

**The pin without the account name.** mcsm's tree must pass its privacy check, which refuses the GitHub account, so the git URL in mcsm's pubspecs cannot name it.
Prefer a neutral URL that git maps through `url.<real>.insteadOf` set by each machine's private setup (Mac, workstation, Windows VM, and the build mirror); prove that `dart pub get` and `flutter build` resolve and lock it on each machine before committing to it.
If pub refuses that, fall back to a recorded pin file (`PRISMARINE_PIN`: the commit) plus a script that checks the commit out into `$MCSM_DATA/prismarine/<sha>` and writes `pubspec_overrides.yaml` path entries; say which one was chosen and why.

**Everything that copies mcsm's tree must carry prismarine too:** the build mirror (`tools/toolchain/sync.sh`), `play.sh`'s archive of HEAD, the corpus sync to the workstation (`corpus_ws.sh sync`), the workstation and Windows builds (`apps/mcsm_player/tool/linux`, `windows`), and agents' worktrees (an override to their prismarine worktree).

## Step 3: lints and machine scripts from prismarine

1. mcsm's gate runs analyze, alloc, same_code, privacy_check, check_links and docs_index from the pinned prismarine checkout with mcsm's config; mcsm's copies are deleted; code_shape runs with mcsm's rule set from config.
2. The heavy-job and measure locks move to `tools/machine/` (one lock directory per machine, both repos' agents); mcsm's `heavy.sh`/`measure.sh` call them. The Wine and VM locks stay in mcsm.
3. mcsm's gate adds the check that the prismarine pin resolves and is an ancestor of prismarine's `main`.

## Checks per step

- prismarine: its gate (step 1 on); clippy and `cargo test` for the moved crates (pad, the cargo hook's test crate).
- mcsm: the land gate; D1 `compare` against the current reference (frames and `audio.wav` identical); the alloc lint count unchanged in total across both repos (mcsm's drop equals prismarine's start); the Windows and Linux player builds once (workstation, Windows VM) to prove the pin resolves there.
- After step 3: one corpus `check` (no rebaseline expected).
